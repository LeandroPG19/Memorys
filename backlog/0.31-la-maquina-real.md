## The batch (code)

| ID | Slice | Why now |
|---|---|---|
| G5 | **Mutation jobs from the RAM that is available, not the total.** `mutants-gate.sh` and `quality-gate.sh` pick `--jobs` from total RAM and cores (63 GB, 24 cores → 6). On 2026-10-14 the WSL VM left ~10 GB free, two builds died in rustc's `handle_alloc_error`, and the gate said so correctly: 48 minutes lost. | It cost a full judge run, and the judge was right to refuse; the choice of jobs was wrong. |
| G6 | **One list of ignored advisories, with owner and expiry.** `rust/deny.toml` and `rust/.cargo/audit.toml` ignore different advisories (`RUSTSEC-2026-0002` only in one) and none carries an owner or a date, which `verificacion.md` requires. | 0.30's G2 made `cargo audit` the only judge of advisories; its exception list is the one that matters. |
| G7 | **A time ceiling per test binary in the judge** (`ci-rapido`: «the judge prints the slowest binaries and has a ceiling per binary»). 0.30 took `v029_accounts_over_real_http` from 553 s to 10.9 s by hand; nothing stops it from drifting back. Two-way, with owner and expiry for any binary above it. | The 0.30 gains are only kept if they are pinned. |
| G8 | **`validar-handoff.sh` sees the `--self-test` blocks of the gate scripts.** Today it compares `#[cfg(test)]` regions of `.rs` only; for the scripts the freeze («the tests did not change between the red commit and the green one») was checked by hand with `sed` + `cmp` in every slice of 0.30. | The two-pass protocol is the point of the six-pack; for scripts it rests on someone remembering. |
| T3 | **No fixed ports in tests.** `v042` binds `18853`; on 2026-10-14 a Windows `TIME_WAIT` on it made `a_daemon_whose_database_is_down_still_answers_200` red on Linux for ~70 s (mirrored networking shares the port table). `v025`, `v027`, `v029_accounts`, `v045` carry fixed ports too (grep before specifying: there may be more). | A flaky red costs a judge run, as G5 did. |
| K4 | **`/health` never says `loaded` for an NLI that is not enabled.** With no NLI model at start the cell resolves to `Unavailable`; `nli_state_from` re-reads `available()` (the file exists) on every poll, so a model installed afterwards reads `loaded` with `device: null` while `enabled()` is false. Found by the review of 0.30; contradicts K3b's own changelog line. | A health endpoint that can say `loaded` for a model nothing loaded. |
| K5 | **The registry keeps why the provider refused when the CPU commit fails too** (today only a `tracing::error!`), and the one search that opens the reranker no longer judges without a registry (`faro.rs`). | The two residues K2 and K3a declared. |
