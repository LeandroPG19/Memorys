# The one list of RustSec advisories this project ignores. scripts/advisory-exceptions.sh
# judges it in merge-gate.sh right after cargo audit, against a cargo audit --json report
# of rust/Cargo.lock made without ignores.
#
# A line: <advisory> <owner> <expires> <reason>
#   advisory  RUSTSEC-YYYY-NNNN.
#   owner     one word.   expires  YYYY-MM-DD, at most 180 days ahead; the day after it, red.
#   reason    the rest of the line, never empty: why it does not reach this binary, and
#             what ends it.
# Red: a line that is malformed or repeated, expired or too far ahead, an advisory the
# report does not carry (it no longer matches anything in Cargo.lock), and any difference
# between this list and the ignore lists of rust/.cargo/audit.toml and rust/deny.toml,
# which are its mirrors: cargo-audit takes only bare IDs there and cargo-deny only id and
# reason, so the owner and the date can live nowhere else.

RUSTSEC-2024-0436 orquestador-0.31 2026-11-30 paste 1.0.15 is unmaintained; a proc-macro that runs at build time only, through tokenizers (macro_rules_attribute) and nalgebra (simba). Ends when both drop it
RUSTSEC-2026-0459 orquestador-0.31 2026-11-30 libsqlite3-sys (C SQLite CVE-2026-119375, fixed in >= 0.39.0) is in Cargo.lock only through sqlx-sqlite 0.9.0, which caps it below 0.38 (it asks for >= 0.30.1, < 0.38.0, so the lock holds an affected version) and which no feature of this crate builds: cargo tree -i libsqlite3-sys --all-features and cargo tree -i sqlx-sqlite --all-features print nothing, so no SQLite is compiled or linked into the binary. Ends when sqlx allows libsqlite3-sys >= 0.39 or leaves sqlx-sqlite out of the lockfile
