# The one list of RustSec advisories this project ignores. scripts/advisory-exceptions.sh
# judges it in merge-gate.sh right after cargo audit, against a cargo audit --json report
# of rust/Cargo.lock made without ignores.
#
# A line: <advisory> <owner> <expires> <reason>
#   advisory  RUSTSEC-YYYY-NNNN.
#   owner     one word.   expires  YYYY-MM-DD, at most 180 days ahead; the day after it, red.
#   reason    the rest of the line, never empty: why it does not reach this binary, and
#             what ends it.
# Red: a line that is malformed or repeated, expired or too far ahead, an advisory the
# report does not carry (it no longer matches anything in Cargo.lock), and any difference
# between this list and the ignore lists of rust/.cargo/audit.toml and rust/deny.toml,
# which are its mirrors: cargo-audit takes only bare IDs there and cargo-deny only id and
# reason, so the owner and the date can live nowhere else.

RUSTSEC-2023-0071 orquestador-0.31 2026-11-30 rsa 0.9.10 (Marvin Attack, no fixed rsa) is in Cargo.lock only through sqlx-mysql, which no feature of this crate builds: cargo tree -i sqlx-mysql prints nothing and cargo deny, which resolves features, never meets it. Ends when sqlx leaves sqlx-mysql out of the lockfile or rsa ships a fix
RUSTSEC-2024-0436 orquestador-0.31 2026-11-30 paste 1.0.15 is unmaintained; a proc-macro that runs at build time only, through tokenizers (directly and through macro_rules_attribute). Ends when tokenizers drops it
RUSTSEC-2026-0459 orquestador-0.31 2026-11-30 libsqlite3-sys 0.30.1 (C SQLite CVE-2026-119375, fixed in >= 0.39.0) is in Cargo.lock only through sqlx-sqlite (sqlx 0.8.6), which no feature of this crate builds: cargo tree -i libsqlite3-sys --all-features and cargo tree -i sqlx-sqlite --all-features print nothing, so no SQLite is compiled or linked into the binary. Ends when sqlx raises its libsqlite3-sys to >= 0.39 or leaves sqlx-sqlite out of the lockfile
